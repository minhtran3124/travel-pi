## 1. Motivation

PR #197 (gh-194) shipped the duplicate-intent warning with four advisories left open (GH #200 items 1–4):

1. `book_hotel`'s `DuplicateBookingError` message interpolates the *new request's* `check_in`/`check_out`/`rooms` while naming the *existing* booking (`booking_service.py:544-549`): an existing 1-room booking + a 3-room request says "…booking X … (3 room(s))".
2. `duplicate_warned_this_turn(tool_name, messages)` (`_idempotency.py:85-113`) refuses `allow_duplicate=True` whenever *any* same-tool duplicate warning sits after the last `HumanMessage`, including a warning about a *different* booking ("book flights A and B, B again is fine" → A warned, B's override refused).
3. `tests/tools/test_booking_duplicate_tools.py` hand-builds the warning `ToolMessage` (`_warning_message`, lines 26-30). If `ToolNode(handle_tool_errors=_tool_error_to_message)` / `describe_tool_failure` stopped carrying the marker, the guard would silently stop working and no test would notice (`grep -rn possible-duplicate apps/api/tests` → 0 hits).
4. In `book_hotel` the duplicate block (line 525) runs before `hotel_service.is_available` (line 553): a sold-out hotel + an identical existing booking prompts "possible duplicate" first and "sold out" only after the traveller confirms.
