# gh-153-eval-hitl-auto-approve — Design

Status: approved in brainstorming (2026-09-07). Lane: normal. Issue #153. Base branch: `feat/agent-eval-pipeline` (PR #157) — the eval runner does not exist on `main` yet.

## Purpose

Let the eval harness grade the booking path. Today every booking-flow golden stops at the `plan` node's `interrupt({"type": "plan_approval", "draft": …})` (`app/agents/nodes.py:275`): the trace has an empty reply and no tool calls, so 17 goldens can never pass and the NotFound / graceful-failure scenarios are never exercised.

## Decision (user, brainstorming)

Opt-in per golden. A new optional `Golden.hitl: Literal["approve","reject"] | None` (default `None` = today's behaviour). When set and the graph stops at a `plan_approval` interrupt, the runner resumes the same thread with `Command(resume={"approved": hitl == "approve"})` — exactly what `app/routers/agent.py:385` does — and grades the state after the resume. The interrupt payload is recorded in `Trace.meta["interrupts"]` either way.

Rejected: approve every interrupt unconditionally (cannot grade the clarification path, e.g. `booking-ambiguous-*` where the right answer is to ask which hotel); record-only without resuming (does not run the booking tools, so the NotFound scenario stays untested).

## Data flow

turn i → `graph.invoke(HumanMessage)` → state stops at `plan` with an interrupt → runner reads `out["__interrupt__"]` → (opt-in) `graph.invoke(Command(resume=…))` on the same `thread_id` → final state → `Trace(reply, tool_calls, flow, meta.interrupts)`.

## Error behaviour

- No interrupt on a `hitl` golden: nothing to resume; record `meta["interrupts"] = []` and grade as usual (the golden's `notes` should say why it expected one).
- Resume raises (graph error after approval): surfaces as the existing `agent_run` check failure (runner already converts exceptions per case).
- `hitl` on a non-booking golden: harmless — no interrupt, no resume.

## Tests / success criteria

- SC-1 runner tests (a)(b)(c) pass with FakeLLM (no key).
- SC-2 `tests/eval` whole suite passes; `--dry-run` lists the `hitl` goldens unchanged.
- SC-3 after the paid run: `booking` capability pass rate rises above the 2/8 baseline and the baseline file is regenerated (`make eval-baseline`) with `run_meta.repeat == 3`.
- SC-4 `make eval-compare` against the regenerated baseline exits 0.

## Out of scope

Changing the product's HITL behaviour (plan node asking clarifying questions instead of interrupting on vague requests) — that is agent work, tracked separately.
