Verdict. Architecture and layering are genuinely good — provider-agnostic init_chat_model, @tool + ToolException + ToolNode self-correction, Command(goto=) handoffs with destinations=, RemoveMessage trimming, MCP annotations, zero-network fakes. But there are 4 correctness/resource bugs that defeat features this PR claims to ship, plus a cluster of 1.x-modernization gaps. Critical — features wired wrong or resource leaks

C1Graph + checkpointer + store rebuilt on every request (the lru_cache is dead code)

Evidence app/routers/agent.py:35–43 — the get_travel_graph dependency calls build_graph(checkpointer=get_checkpointer(), store=get_store()) fresh per request. app/agents/graph.py:80–86 defines an @lru_cache'd get_compiled_graph() that is never called; app/core/lifespan.py:65 builds app.state.agent_checkpointer once that the router also never uses.

Impact Each /agent/chat & /agent/stream re-compiles 6 subgraphs and opens a new sqlite3.connect / PostgresSaver.from_conn_string(url).__enter__() + .setup() (DDL) and a new PostgresStore.__enter__() + .setup() — none ever closed. Under load this exhausts Postgres connections / SQLite handles.

Fix Build graph + checkpointer + store once in lifespan, hold on app.state, and return it from get_travel_graph. Delete the dead get_compiled_graph or use it. Highest impact, smallest diff.

Ref langgraph/persistence

C2Rolling summary is computed and old messages deleted — but the summary is never used

Evidence app/agents/nodes.py:50–55 writes {"summary": …, "messages": <RemoveMessages>}, actively dropping older turns. Nothing reads state["summary"] (grep: only the writer + the field decl at state.py:23). Supervisor and every sub-agent build prompts from state["messages"] only.

Impact Summarization makes the agent worse than doing nothing — it deletes history and throws the compression away (net context loss).

Fix Minimal: prepend SystemMessage(f"Conversation so far: {state['summary']}") when set. Idiomatic: attach SummarizationMiddleware(model=fast_llm, trigger=("tokens", N), keep=("messages", M)) to create_agent (note new trigger/keep API; max_tokens_before_summary/messages_to_keep are deprecated).

Ref SummarizationMiddleware

C3Long-term memory: semantic search is non-functional, and user_id is model-supplied

No index → query ignored app/memory/store.py:29,34 creates PostgresStore.from_conn_string(url) and InMemoryStore() without an index= config. store.search(ns, query=…) only ranks semantically when built with index={"dims": …, "embed": embeddings, "fields": […]}. So get_user_preferences(query=…) (tools/memory_tools.py:33) silently returns by recency, ignoring the query.

Model-supplied user_id save_user_preference(user_id, …) / get_user_preferences(user_id, …) (tools/memory_tools.py:21,33) make the model pass user_id — it can cross-wire and read/write another traveller's memories (the namespace ("users", user_id, "prefs") is the isolation boundary). The real user_id already lives in TravelAgentState.user_id.

Fix (1) construct the store with an index= config wired to get_embeddings(). (2) Inject user_id from state via Annotated[str, InjectedState("user_id")] (hidden from the schema), or the 1.x ToolRuntime idiom (see L4).

Refs long-term-memory · semantic memory (blog)

C4/agent/stream leaks internal node output (router/summarizer/reflection) to the user

Evidence app/routers/agent.py:101–113 streams stream_mode="messages" and yields chunk.content for every model call, discarding metadata (_meta). Tokens from the supervisor router, the summarizer, and the reflection critic stream too — so the SSE feed can contain the rolling summary text or the literal OK/REVISE verdict (nodes.py:76) interleaved with the answer.

Fix stream_mode="messages" yields (chunk, metadata) — filter on metadata["langgraph_node"] (or model tags) and only emit the user-facing node. Also: anonymous streams collapse onto conv_stream (agent.py:99), colliding all unnamed sessions on one thread_id.

Ref langgraph/streaming

Medium — correctness smells & 1.x persistence/lifecycle

M1HITL plan_node is dead code, yet SUMMARY claims "plan HITL" shipped

app/agents/nodes.py:92–100 defines the interrupt() approval node, but it is never added to any graph and has no test; SUMMARY.md:41 lists it as done. Either wire it in (conditional edge before destructive booking, resumed via Command(resume=…)) or remove it and correct the SUMMARY. 1.x prefers HumanInTheLoopMiddleware(interrupt_on={"book_hotel": True}).

M2load_context_node appends a SystemMessage via add_messages → lands after the human turn

app/agents/nodes.py:42 returns {"messages": [SystemMessage(…)]}. add_messages appends, so trip context ends up after the HumanMessage → [System, Human, System]. A mid-conversation system message is ignored by some providers and rejected by Anthropic (your stack supports langchain-anthropic). Fix carry trip context in a state field / render into the system prompt — don't push it into messages.

M3Sync savers/stores under an async graph + manual __enter__() lifecycle

  • Match saver to mode — use AsyncSqliteSaver/AsyncPostgresSaver for async graphs. The single shared sqlite3 connection (check_same_thread=False, checkpointer.py:46) is unsafe for concurrent threadpool writes → "database is locked".
  • PostgresSaver.from_conn_string(url).__enter__() (checkpointer.py:54) and PostgresStore…__enter__() (store.py:29) enter a CM that is never exited (the C1 leak).

Fix async with AsyncPostgresSaver.from_conn_string(dsn) as cp: await cp.setup() in lifespan; hold on app.state. (Checkpoint ≥3.0 is correct — patches CVE-2025-64439; keep that floor.)

Refs persistence · CVE-2025-64439

M4Langfuse handler rebuilt per request + likely-invalid v4 kwarg

app/agents/observability.py:29–43 — callbacks() runs per request and each call builds a new Langfuse(...) client and CallbackHandler(public_key=…). In Langfuse v3+/v4, CallbackHandler() takes no key kwargs (reads the singleton get_client()) — so public_key= is ignored / may raise. The metadata path is correct. Fix one cached client + handler at startup; verify the constructor against installed 4.12 (untested — Langfuse off in CI).

Ref Langfuse v2→v3 upgrade

M5RAG uses the legacy class and a hand-rolled hybrid that isn't truly hybrid

  • app/rag/embeddings.py:44 uses PGVector; langchain-postgres ≥0.0.12 ships PGVectorStore (v2: PGEngine, async, HNSW, postgresql+psycopg://).
  • app/rag/retriever.py re-ranks the same similarity_search candidate set by lexical overlap — the lexical leg can never surface a keyword match dense search missed. v2 provides native RRF via HybridSearchConfig(fusion_function=reciprocal_rank_fusion).
  • Metadata filters applied after fetch/rank (retriever.py:48) can starve results below k; push filter= into similarity_search.
  • app/rag/ingest.py:49 add_documents(docs) passes no ids= → re-ingest duplicates every doc. Derive stable ids from place.id.

Refs langchain-postgres · reciprocal_rank_fusion

Low — polish & modernization

  • L1 — No temperature=0. clients/llm.py:51 passes no temperature; the router (with_structured_output) and tool-calling sub-agents want deterministic decoding.
  • L2 — Reflection critic under-informed & brittle. nodes.py:75–76 judges with only [system, last] (no user question) and string-matches "REVISE". Pass the user turn; use with_structured_output(Verdict).
  • L3 — Sync nodes for real I/O. subagents/_base.py:35, supervisor.py:38, nodes.py call llm.invoke in an async graph. Prefer async def + await llm.ainvoke.
  • L4 — Modernization: create_agent + middleware. LangChain 1.0 makes the hand-rolled ReAct subgraph, summarizer, and HITL node largely unnecessary: create_agent returns a compiled graph; SummarizationMiddleware (fixes C2), HumanInTheLoopMiddleware (fixes M1), dynamic_prompt, and ToolRuntime (replaces InjectedStore/InjectedState, fixes C3 injection) are the supported seams. langgraph-supervisor can replace make_supervisor. Optional — but deletes code and aligns with library direction. (ToolNode/tools_condition are still current; only create_react_agent from langgraph.prebuilt is superseded — you don't use it.)
  • L5 — MCP annotations. mcp/server.py:39 sets readOnlyHint/destructiveHint; add idempotentHint (reads) and openWorldHint (weather/route hit external APIs). Confirm no print() in the tool path (stdout corrupts stdio JSON-RPC — log to stderr).
  • L6 — _PROVIDER_KEY_FIELD KeyError. clients/llm.py:48 indexes with s.llm_provider; use .get(...) with a clear error if the enum widens.
  • L7 — Test gaps. No tests exercise /agent/stream, the interrupt/HITL path, summarize-then-recall, or multi-user memory isolation — each maps to a bug above (C4, M1, C2, C3).

What's genuinely well done

Provider-agnostic init_chat_model factory + clean FakeLLM double · @tool + ToolException → ToolMessage(status="error") self-correction · Command(goto=) handoffs with destinations= hints (correct 1.x routing idiom) · RemoveMessage trimming (correct deletion sentinel) · per-domain tool binding to avoid sprawl · MCP server reusing the single tool registry · checkpoint floor ≥3.0 (CVE-patched) · graceful degrade-to-in-memory everywhere · zero-network test suite.

Priority order to fix

  1. C1 — per-request rebuild/leak. Highest impact, smallest diff: build once in lifespan.
  2. C2 + C3 — summary never used; memory search dead + user_id injection. Silently break two headline features.
  3. C4 — stream leaks internal output. User-visible correctness.
  4. M1–M5 cleanup pass; M4/M5 verify against the installed 4.12 / langchain-postgres first.
  5. L4 modernization as a follow-up branch once bugs are closed.
Version caveat. Confirm the v3 streaming object (stream_events(version="v3")), durability modes, and the exact Langfuse 4.12 CallbackHandler signature against your pins before adopting — the stream_mode / interrupt / Command(resume=) APIs relied on here are stable across all of 1.x.
