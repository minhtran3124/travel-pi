# Files

- [Agent graph and supervisor routing](graph-and-supervisor.md) - How the LangGraph travel-agent graph is assembled and how a turn flows from the PII guardrail through context loading, summarization, supervisor intent classification, task routing (single specialist, booking HITL plan, or parallel synthesis workers), synthesis and the bounded reflection loop.
- [Guardrails: PII, memory poisoning and human-in-the-loop](guardrails-pii-and-hitl.md) - The safety layers around the travel agent — credit-card redaction before any model call, the booking plan-approval interrupt and resume path, confirm/ownership protections on destructive tools, the trip guard, and the deterministic write/read guard plus prompt wrapping that contain long-term memory poisoning.
- [LLM providers and per-agent configuration](llm-providers-and-agent-config.md) - How chat models are built provider-agnostically, the static provider catalog with per-provider API keys and gateway base URLs, the fast vs full model tiers, DB-backed per-agent overrides served through a poll-refreshed in-process cache that triggers a graph rebuild, and the deterministic FakeLLM used by the test suite.
- [Conversation memory and persistence](memory-and-persistence.md) - The three persistence layers behind an agent conversation — the LangGraph checkpointer (Postgres or ephemeral in-memory) keyed by thread id, the embedding-indexed long-term Store with per-user preference, procedural and episodic namespaces, and the conversations/messages tables — plus rolling summarization and the best-effort background memory extraction that writes to the store after each turn.
- [Observability, turn metrics and cost](observability-and-metrics.md) - How each agent turn is measured and recorded — the per-turn TurnMetricsHandler callback that collects token, latency, node-timing and step data without ever storing user content, the agent_runs and agent_run_steps tables, USD cost estimation, prompt-version attribution per step, optional Langfuse tracing, and the prompt-cache reporting scripts.
- [Prompt registry and versioning](prompt-registry.md) - How agent system prompts are stored as versioned Markdown files per name, selected by the active.yaml pointer through the in-memory PromptRegistry, composed with the shared communication_style guideline, snapshotted into the compiled graph for run attribution, browsed and diffed in the dashboard, and how to change a prompt safely.
- [Travel knowledge RAG](rag-travel-knowledge.md) - How the concierge's travel-knowledge retrieval works — seeded visa, local-tip and country-summary rows serialized to prose and embedded into a pgvector or in-memory vector store at startup as an idempotent upsert, hybrid semantic-plus-lexical retrieval with Reciprocal Rank Fusion and metadata filters, the tool that exposes it, and how it degrades when the store or embeddings fail.
- [Specialist sub-agents and the tool registry](specialists-and-tools.md) - How each of the five specialists (planner, concierge, journal, booking, budget) is compiled as a small ReAct subgraph with a trip guard, how the tool registry groups tools by domain and derives read-only/destructive metadata, how injected state and store arguments must be declared, the clarification and date-resolution tools, and how tool failures are classified so the model never narrates a deterministic fault as an outage.
- [Agent state, runtime context and reply language](state-context-and-language.md) - The TravelAgentState channels and their reducers, the per-run AgentContext (tier, authentication, reflection and memory toggles, allowed specialists, timezone), how context blocks are folded into one leading system message, trip-facts and current-date grounding, and the single supervisor-detected language that every reply and code-authored system message follows.
- [Agent chat endpoints, SSE streaming and side panels](streaming-and-side-panels.md) - The /agent REST surface (chat, stream, conversations, messages, manifest, claim, feedback), how a turn is set up before the graph runs, the typed Server-Sent Events taxonomy and the mapper that turns a LangGraph stream into it with de-duplication and drafts reset, side-panel artifacts and their localization, the persistence and run-recording wrappers, follow-up suggestions, and the failure and interrupt semantics a client can rely on.
- [Trip-research deep agent](trip-research-deep-agent.md) - The second, independent LangGraph graph (built with deepagents) that researches one trip into a dossier and a machine-readable proposal. Covers how it is built (per-dimension subagents, skills, store-backed files, write permissions, rubric grader), run bookkeeping and concurrency in ResearchService, the background runner, the in-process progress bus and SSE stream, the premium REST routes, and the chat graph's research launcher node.
